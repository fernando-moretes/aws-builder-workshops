<Steps>

1. **Install in your project folder.**

   ```sh
   npx -y moretes-builder-workshops init kiro --lang en
   ```

   ```text
   ✓ .kiro/settings/mcp.json
   ✓ .kiro/skills/builder-workshops
   ✓ .kiro/steering/builder-workshops.md
   ```

   Servers that are already in `mcp.json` are preserved.

2. **Check the server.** Open Kiro's MCP panel and see whether `builder-workshops` shows as connected, with 10 tools.

3. **Make your first request.**

   > Use builder-workshops. Guide me through mission 3, one step at a time, and ask me for my hypothesis before you explain.

4. **Start your experiment.**

   > I want to start my first experiment with the builder-workshops skill. Do not write for me.

</Steps>

## What each file does

| File | Role |
|---|---|
| `.kiro/settings/mcp.json` | Registers the server. Applies to this workspace |
| `.kiro/skills/builder-workshops/` | The skill, loaded when the request matches it |
| `.kiro/steering/builder-workshops.md` | Project rules, included manually: call it in the chat with `#builder-workshops` |

Want it in every project? Copy the skill to `~/.kiro/skills/` and the server to `~/.kiro/settings/mcp.json`. The same `mcp.json` works in Kiro CLI.

## Inside this repository

The repo already comes configured: open the folder in Kiro and the server runs from the local code.

:::caution[Not yet tested in a real Kiro]
The paths follow the [Kiro documentation](https://kiro.dev/docs/mcp/configuration/) and the server is tested with the official MCP client, but no test has been done inside Kiro itself so far. If you test it, [tell us how it went in issue #1](https://github.com/fernando-moretes/aws-builder-workshops/issues/1).
